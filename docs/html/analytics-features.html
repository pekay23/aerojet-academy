01 · Overview

Three analytics surfaces

Aerojet Academy exposes analytics through three distinct surfaces. All require at least STAFF role; ADMIN and SUPER_ADMIN inherit full access.

Operational

Staff Dashboard

Live KPIs, revenue chart, Go/No-Go meter, pending payments, and real-time alert banner.

/staff/dashboard
Product

Analytics Dashboard

Funnels, cohort retention, feature adoption, page views, and per-user event timelines.

/staff/analytics
Business Intelligence

Reports

Revenue, enrollment, pool fill, attendance, exam trends, and year-on-year comparisons with CSV export.

/staff/reports
Storage model
All behavioural events are written to AuditLog with entity = 'ANALYTICS'. The action field holds the event name; changes holds the structured payload. This reuse means analytics queries share the audit-trail table.
02 · Dashboards

Operational & product views

Staff Dashboard

/staff/dashboard — the main operational view. Auto-refreshes every 60 seconds.

  • Stat cards — active users, pending applicants, active students, pending payments
  • Revenue chart — 6-month area chart with target line (app/staff/_components/RevenueChart.tsx)
  • Go/No-Go meter — seat fill % + confirmed revenue for next active exam event
  • Pending payment approval cards
  • Admissions pipeline widget
  • AlertsCenter banner — 7 real-time alert checks, 5-min server cache

Analytics Dashboard

/staff/analytics?tab=... — product/behavioural analytics with six tabs:

03 · Reports

Financial, enrollment, pool & exam reports

Financial Reports

Revenue aggregates, payment status breakdowns, and programme-type analysis.

EndpointFileReturns
GET /api/staff/reports/revenueapp/api/staff/reports/revenue/route.tsTotal/approved/pending payments, revenue by referenceType, wallet balance stats

Lib functions in lib/analytics/reports.ts: getFinanceReportSummary, getRevenueByProgrammeType, getPaymentMethodBreakdown, getMonthlyRevenueData, getPaymentStatusBreakdown, getRevenueReport.

PDF export is dormant
lib/analytics/pdf-export.ts contains generateFinancialPDF() (jsPDF + jspdf-autotable) but no API endpoint or UI trigger is wired.

Enrollment Reports

GET /api/staff/reports/enrollment — totals, by status, by course, by month. Lib: getEnrollmentTrends().

Pool & Exam Reports

EndpointReturns
GET /api/staff/reports/poolsPool counts, status breakdown, avg members, confirmed revenue
GET /api/staff/reports/roster/[poolId]CSV roster download (candidate name, reg number, module, status). Audit-logged.

Admissions Pipeline

GET /api/staff/admissions/pipeline — stage funnel, programme breakdown, outcomes, 7-day recent activity, active intake cycles. Also rendered as a widget on the Staff Dashboard.

CSV Data Exports

GET /api/staff/export?type=students|pools|finances|audit-logs — date-bounded CSV exports with a 50,000 row cap. Triggered from the Period Filter on /staff/reports.

05 · Monitoring & Alerts

Real-time alerts, cron jobs, and email monitoring

Dashboard Alerts

The AlertsCenter banner on /staff/dashboard polls every 60 seconds. Server-side caching provides a 5-minute TTL via unstable_cache.

#AlertSeverityThreshold
1Payments pending > 7 daysWARNINGCRITICAL if > 10
2GDPR DSRs past 30-day SLACRITICAL—
3Referrals with fraudScore >= 50 unreviewedWARNING—
4Exam bundles expiring in 7 days with unused resitsINFO—
5UploadThing files unmirrored > 24hINFOWARNING if > 100
6Email delivery failures in last 24hWARNINGCRITICAL if >= 10
7Internal exam reports pending reviewINFOWARNING if >= 5

Cron Jobs

CronSchedulePurpose
check-poolsDaily 01:00Auto-confirm/fail exam events via Go/No-Go evaluation at payment deadline
check-eventsDaily 01:00Auto-complete past exam events
sync-checkMon 04:00Neon ↔ Supabase drift detection (> 0.1% → AuditLog)
supabase-mirrorDaily 04:30Nightly UploadThing → Supabase storage mirror
scheduled-reportsMon 08:00DISABLED — would email Board Insights Report
gdpr-retentionMon 03:00GDPR retention sweep

Email Delivery Log

Every outbound email writes an EmailDelivery row with status, attempts, error, and messageId. View at Settings → Email Delivery (filterable, searchable, paginated). Dashboard alert fires when any send fails in the last 24 hours; CRITICAL at >= 10 failures.

Where Events Are Emitted

EventFileTrigger

Client-Side Tracking

hooks/useAnalytics.ts provides useAnalytics(), useSearchTracking(), and useFeatureTracking(). Note: the hook is not mounted in the root layout, so client-side page view tracking is only active where explicitly used.

Forecasting

lib/analytics/forecasting.ts provides:

  • getRevenueForecast() — linear regression + EMA blend, 6-month outlook
  • getEnrollmentPipeline() — applicant→student conversion + prediction
  • detectTrends() — z-score anomaly detection on revenue/enrollments/passRate
07 · Data Models

Schemas that power analytics

AuditLog (Central Event Store)

The primary analytics event store. All behavioural events are written here with entity = 'ANALYTICS'.

FieldTypePurpose
userIdString?Acting user
actionStringEvent name (e.g. PAGE_VIEW)
entityString'ANALYTICS' for tracked events
entityIdString?Related record ID
descriptionString?Human-readable summary
changesJson?Structured payload
ipAddressString?Client IP
userAgentString?Client user agent
createdAtDateTimeEvent timestamp

Companion: AuditLogArchive for archived rows.

EmailDelivery

Tracks every outbound email with status, attempts, error, and provider messageId. Indexed on status+createdAt, recipient, userId.

FileUpload (Sync Monitoring)

mirroredAt and supabasePath track the nightly UploadThing → Supabase mirror backlog. Used by dashboard alert #5.

Referral (Fraud Analytics)

fraudScore (0–100), fraudReasons[], reviewedAt, signupIpHash. Used by dashboard alert #3.

Supporting Models

ExamEvent, ExamPool, PoolMembership, ExamBooking, ExamResult, WalletTransaction, PaymentMilestone, ModularEnrollment, SystemSetting, DataSubjectRequest.

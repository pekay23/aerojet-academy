Codebase Audit Report — 2026-05-17

Comprehensive audit across 4 phases: Auth & Security, Database & Data Layer, Frontend & Performance, Testing & Docs.

Status (2026-05-20): All CRITICAL/HIGH findings resolved or intentionally deferred. See 2026-05-20-comprehensive.md for the full cross-check with file:line evidence and the consolidated verification log. Original findings preserved below for historical context.

01 · CRITICAL

CRITICAL

SEC-1: Plaintext Passwords Returned in API Responses

  • app/api/staff/users/[id]/reset-password/route.ts:65 — returns tempPassword in JSON response body alongside sending it via email
  • app/api/staff/students/import/route.ts:712-724 — bulk import returns array of all generated passwords in response
  • Fix: Remove tempPassword from response bodies. Email is the only safe delivery channel.

SEC-2: iCal Calendar Endpoint Has No Authentication

  • app/api/calendar/[userId]/route.ts — accepts a bare userId URL param, returns full .ics with exam bookings, enrollments, classes — no session check
  • Fix: Add getAuthSession() check, verify session.user.id === userId or caller is staff. For public calendar apps, use a per-user signed token with expiry.

SEC-3: Unsubscribe Endpoint — User Enumeration + Unauthenticated Modification

  • app/api/unsubscribe/route.ts:26 — returns 404 "Email not found" (leaks existence), no rate limiting, no auth
  • Fix: Return uniform success response regardless. Add rate limiting. Require signed unsubscribe token.

SEC-4: GET /api/staff/users Missing Role Check

  • app/api/staff/users/route.ts:6-8 — only checks if (!session), any authenticated user (student, applicant) can list all users with emails, phones, roles
  • Fix: Add if (!['ADMIN','SUPER_ADMIN','STAFF','EXAMINER'].includes(session.user.role)) return apiUnauthorized()

SEC-5: 2FA Setup Accepts Client-Supplied Secret

  • app/api/auth/2fa/verify/route.ts:17-28 — accepts secret from request body and saves it directly. Attacker can register 2FA with a secret they control.
  • Fix: Store generated secret server-side temporarily (session or short-lived DB record) during the generate step. verify retrieves it server-side — never accept from client.

DB-1: AdminCalendarEvent Missing from SOFT_DELETE_MODELS

  • Has deletedAt field and @@index([deletedAt]) but not in lib/prisma/soft-delete-extension.ts
  • All queries return soft-deleted records to users
  • Fix: Add 'AdminCalendarEvent' to SOFT_DELETE_MODELS

DB-2: $queryRawUnsafe with SELECT * Bypasses Soft-Delete

  • lib/pools/withdraw.ts:37, lib/pools/join.ts:136 — raw SQL bypasses soft-delete extension
  • Fix: Replace with Prisma model queries + separate advisory lock via $executeRaw

CI-1: CI Workflow Uses Node 20, package.json Requires Node 24

  • .github/workflows/ci.yml specifies node-version: '20', engines field says "node": "24.x"
  • Fix: Update CI to node-version: '24'

CI-2: No .env.example File Exists

  • docs/guides/setup.md references cp .env.example .env.local but file doesn't exist
  • Fix: Create .env.example with placeholder values for all required env vars

CI-3: Supabase Env Var Name Mismatch

  • .env uses NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY
  • lib/supabase/client.ts reads NEXT_PUBLIC_SUPABASE_ANON_KEY
  • Two separate Supabase client stacks (lib/supabase/ and utils/supabase/) use different var names
  • Fix: Standardize on one name across all files
02 · HIGH

HIGH

SEC-6: In-Memory Rate Limiting — Ineffective in Production

  • lib/security/rate-limit.ts uses Map<string, ...> — resets on cold start, per-instance in serverless
  • Fix: Replace with Redis-backed rate limiter (e.g., @upstash/ratelimit)

SEC-7: No TOTP Replay Protection

  • lib/auth/totp.ts allows the same code to be used multiple times within the 90-second window
  • Fix: Store last-used TOTP counter in user record, reject codes with counter <= last-used

SEC-8: Passkey Login Missing Challenge-User Validation

  • app/api/auth/passkey/login-verify/route.ts:44-48 — doesn't verify storedChallenge.userId === passkey.userId
  • Fix: Add user-ID consistency check before verifyAuthenticationResponse

SEC-9: requireUserVerification: false in Passkey Flows

  • Both register-verify and login-verify set this — allows authenticators without biometric/PIN
  • Fix: Set requireUserVerification: true

SEC-10: Token-Based Auto-Login Skips Account Status Check

  • lib/auth/auth-options.ts — pk_ token login path doesn't check user.status (suspended/archived users can authenticate)
  • Fix: Add status check in token-based login branch

SEC-11: No Rate Limiting on resend-verification Endpoint

  • app/api/auth/resend-verification/route.ts — unlimited verification emails, leaks whether email is verified
  • Fix: Add IP-based rate limiting, return uniform response

SEC-12: Password Reset/Email Verify/Passkey Bridge Share Single Token Field

  • All use verifyToken/verifyTokenExpires — requesting one invalidates the others
  • Fix: Separate token storage by purpose (distinct fields or a PendingToken table)

SEC-13: No Root middleware.ts — Route Protection Relies Entirely on Per-Route Checks

  • A missed getAuthSession() call (e.g., SEC-4) is a silent vulnerability
  • Fix: Implement root middleware enforcing role checks for /api/staff/**, /api/student/**, etc.

DB-3: N+1 Query Pattern in payment-deadlines Cron

  • app/api/cron/payment-deadlines/route.ts:30-141 — O(events x bookings) DB round-trips
  • Fix: Batch idempotency check, batch writes

DB-4: N+1 + Unbounded Fetch in milestone-reminders Cron

  • app/api/cron/milestone-reminders/route.ts — no take limit, 2 queries per milestone
  • Fix: Add pagination, batch the idempotency check

DB-5: Unbounded findMany in reconcile/pending

  • app/api/staff/finance/reconcile/pending/route.ts:10 — no take or pagination
  • Fix: Add take: 100 and paginate

DB-6: staff/payments Hardcoded take: 50 Without Pagination

  • app/api/staff/payments/route.ts:46 — computes total but caps at 50 with no skip/page
  • Fix: Add proper pagination params like payments/pending/route.ts

DB-7: RLS Per-Query Transaction Overhead

  • lib/prisma/rls-hardened.ts:155-164 — every non-admin read opens a separate transaction
  • Non-admin pages firing 5-10 concurrent reads open 5-10 transactions each with 2x set_config round-trips
  • Fix: Batch RLS setup per-request rather than per-query

FE-1: YoYCharts.tsx Imports Recharts Directly (~200KB)

  • app/staff/reports/_components/YoYCharts.tsx — no next/dynamic wrapper
  • Fix: Wrap with dynamic(() => import('./YoYCharts'), { ssr: false })

FE-2: RichTextEditor.tsx Imports TipTap Directly (~150KB)

  • components/shared/RichTextEditor.tsx — any consumer gets TipTap in their bundle
  • Fix: Consumers should import via next/dynamic

FE-3: staff/settings/page.tsx Imports EmailPreviewsPage Directly

  • Bundles full email preview client component regardless of active tab
  • Fix: Use next/dynamic for tab content

FE-4: ~55 Route Segments Missing loading.tsx

  • Entire (auth) portal: 7 pages, zero loading.tsx files
  • Entire instructor portal sub-routes: 12 pages, only root loading exists
  • 20+ (public) pages including all course detail pages
  • 12+ staff pages including attendance, classrooms, ATA chapters
  • Examiner root, multiple student pages
  • See Phase 3 report for complete list

FE-5: Sequential Awaits in Critical Pages

  • app/applicant/exam-only/top-up/page.tsx — 8-9 sequential DB queries
  • app/applicant/pathway/page.tsx — 5+ sequential queries (core enrollment flow)
  • app/applicant/wallet-top-up/page.tsx — 5 independent awaits
  • app/instructor/layout.tsx — sequential when staff layout correctly uses Promise.all
  • app/staff/classes/[id]/roster/page.tsx — 4 sequential queries
  • Fix: Group independent queries with Promise.all

TEST-1: Zero Tests for Critical Business Logic

  • lib/pools/operations.ts (joinPool — race-condition critical), lib/auth/auth-options.ts (credentials provider, 2FA), payment approval handler, wallet charge, encryption, email service, all 13 cron handlers, all server actions, internal exam engine, admissions state machine
  • Fix: Prioritize tests for financial and auth paths

TEST-2: "Integration Tests" Only Assert on Static Fixtures

  • tests/integration/api/payment-approval.test.ts, pool-join.test.ts, tests/integration/workflows/*.test.ts
  • Test fixture shape, not behavior
  • Fix: Replace with actual handler/workflow tests

TEST-3: E2E Tests Depend on Seeded Credentials

  • Tests use student@aerojet-academy.com / Student@2026 etc. — fail if seed not run
  • pool-joining.test.ts has soft skip that silently passes with no pool
  • Fix: Add setup/teardown, remove silent skips

TEST-4: deploy-staging.yml Runs Migrations After Deployment

  • App deploys with new code but old schema — window of failures
  • Fix: Run migration step before deployment
03 · MEDIUM

MEDIUM

SEC-14: CSP Header Only Has frame-ancestors 'self'

  • next.config.ts:41-44 — no default-src, script-src, connect-src, etc.
  • Fix: Implement full CSP policy

SEC-15: EXAMINER Role Inconsistency

  • isStaff() excludes EXAMINER, requireStaff() includes it, RLS bypass includes it
  • SQL is_admin_or_staff() function only has SUPER_ADMIN/ADMIN/STAFF — EXAMINER bypasses app-level RLS but SQL RLS still restricts, causing write failures
  • Fix: Align EXAMINER treatment across all helpers and SQL

SEC-16: STAFF Can Hard-Delete Users

  • app/api/staff/users/[id]/route.ts:215-267 — only requires STAFF for ?hard=true
  • Fix: Require ADMIN/SUPER_ADMIN for hard delete

SEC-17: me/study-pathway Accessible by Any Role

  • Any authenticated user can create a studentProfile for themselves
  • Fix: Restrict to APPLICANT/STUDENT roles

SEC-18: TOTP Comparison Not Timing-Safe

  • lib/auth/totp.ts:49 — uses === instead of crypto.timingSafeEqual
  • Fix: Use crypto.timingSafeEqual(Buffer.from(generated), Buffer.from(token))

SEC-19: scryptSync Blocks Event Loop in Encryption Module

  • lib/security/encryption.ts:12 — called on every encrypt/decrypt
  • Fix: Cache derived key or use pre-derived master key

SEC-20: Resend Webhook Processes Unverified Payloads

  • app/api/webhooks/resend/route.ts:39-42 — if RESEND_WEBHOOK_SECRET not set, processes payload without signature check
  • Fix: Reject with 503 if secret not configured

SEC-21: SUPER_ADMIN Blocked from Email Preview

  • app/api/staff/email-preview/route.ts:9 — checks for ADMIN and STAFF only
  • Fix: Include SUPER_ADMIN in role check

SEC-22: role Field in updateUserSchema Allows STAFF to Change Roles via PATCH

  • app/api/staff/users/[id]/route.ts:42 — bypasses dedicated /role endpoint permission check
  • Fix: Remove role from updateUserSchema

SEC-23: Unbounded Financial Export

  • app/api/staff/export/route.ts:55-68 — no take limit on walletTransaction.findMany
  • Fix: Add limit, date-range params, or streaming

DB-8: 10 Models Use Bare String for Status Instead of Enums

  • AttendanceRecord, PoolWaitlist, Invoice, FullTimeEnrollment, OjtPeriod, PaymentMilestone, TuitionRun, TuitionBooking, ExamBundle, Referral
  • Fix: Define proper enums

DB-9: serializePrisma Fails on BigInt/Bytes

  • Passkey.counter is BigInt, Passkey.publicKey is Bytes — JSON.stringify will throw on BigInt
  • Fix: Add typeof data === 'bigint' and Buffer.isBuffer(data) branches

DB-10: AcademicYear.isActive and Semester.isActive Lack Indexes

  • Commonly filtered fields with no @@index
  • Fix: Add @@index([isActive])

DB-11: INSTRUCTOR Excluded from RLS Bypass

  • Pays per-query transaction overhead unnecessarily
  • Fix: Add to bypass list (align with SQL policies)

DB-12: Production Pool max: 20 Dangerous in Serverless

  • lib/prisma/db-base.ts:57-64 — 10 concurrent Lambda instances x 20 connections = 200, exhausts Neon limits
  • Fix: Reduce pool size, ensure pooler URL is used

FE-6: app/staff/academic/scheduling/page.tsx — Client Component Fetching in useEffect

  • Should be server component with client sub-component
  • Fix: Restructure as RSC

FE-7: No server-only Guards on Server-Only Lib Files

  • Accidental client import of server code won't error at import time
  • Fix: Add import 'server-only' to lib/prisma/, lib/auth/, lib/email/

FE-8: Examiner Layout Missing id="main-content"

  • Breaks skip-navigation links for screen readers
  • Fix: Add id="main-content" to examiner <main>

DOC-1: system-overview.md Shows Wrong Next.js/React Versions

  • Says "Next.js 15, React 18" — actual is Next.js 16.2.4, React 19.2.4
  • Fix: Update

DOC-2: SECURITY.md/known-issues.md Wrong otplib Version

  • Documents v5 API, actual installed version is v13
  • Fix: Update to match reality (v13, custom TOTP for verification)

DOC-3: DEPLOYMENT.md Missing/Extra Cron Jobs

  • Missing: /api/cron/scheduled-reports (in vercel.json)
  • Exist but unregistered in vercel.json: aptitude-reminders, interview-reminders, modular-deadlines
  • Fix: Sync docs, vercel.json, and route files

DOC-4: Tailwind v4 with v3-Style Config

  • tailwind.config.ts uses deprecated v3 API (Config type, theme.extend, plugins)
  • Fix: Migrate to v4 CSS-first @theme config or verify compat shim works

DOC-5: bun vs npm Inconsistency

  • SETUP.md says bun install, CI uses npm ci, pre-push runs npm test
  • Fix: Standardize on bun throughout

DOC-6: Vitest Coverage Misses app/api/ Routes

  • Config only includes lib/**, hooks/**, components/**
  • Fix: Add app/api/** to coverage includes

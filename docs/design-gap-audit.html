Exam Bundle System

Critical

1a. No DB link between bookings and bundles

ExamBooking has no bundleId FK — once a bundle-funded booking is created, the association is lost permanently.

lib/pools/join.ts:279 creates bookings without persisting bundleId

1b. EXHAUSTED enum value missing

useBundleSeat() at lib/pools/bundles.ts:196 sets status: 'EXHAUSTED' but ExamBundleStatus enum only has ACTIVE / EXPIRED / USED / CANCELLED.

Will throw a Prisma validation error at runtime when all seats are used.

1c. Free resits not tracked or enforced

lib/enrollment/exams.ts:155 — bookResitExam() always charges full €480 fee, ignoring bundle entitlements.

No freeResitsIncluded / usedFreeResits fields on ExamBundle. Neither students nor staff can see free resit balance.

Business rules: Twin Pack = 1 free resit, Four Pack = 2 free resits

1d. Staff-created bundle bookings bypass bundle system

app/api/staff/students/[id]/book-exam/route.ts — setting bookingType to TWIN_PACK / FOUR_PACK just sets a label. No ExamBundle record is created.

1e. BookingEntitlement model is dead code

Exists in Prisma schema but never created anywhere in application code — fully orphaned.

1f. Pack seat counts not visible

app/staff/_components/ExamBookingsTable.tsx shows "twin pack" as text but not "2/2 booked" usage indicator.

Exam Execution Pipeline

Critical — ~30%

2a. No exam sitting creation workflow

ExamSitting model exists in schema but there is no staff UI or API to create sittings for an exam event. Events can be created but cannot progress to actual exam administration.

2b. No examiner result entry

No UI for examiners to enter or upload exam results per sitting. ExamResult records are created only via staff manual entry on ExamsTab. No bulk result upload (CSV import or batch entry form).

2c. No certificate generation

Schema has certificate-related fields but no generation logic. No PDF certificate template, no issuance workflow, no verification endpoint for external parties.

2d. No exam event lifecycle management

Events go from SCHEDULED → ? — no IN_PROGRESS or COMPLETED state transitions. No "start exam" / "end exam" workflow for day-of administration. No attendance marking for exam sittings.

2e. Exam scheduling gaps

Conflict detection exists for examiner/venue overlap. Missing: candidate notification when assigned to a sitting, pre-exam checklist/requirements verification.

3

Pool System

High — ~60%

3a. Pool confirmation flow unclear

Students join pools but the path from "pool member" → "confirmed booking" → "assigned to sitting" is incomplete. confirmPool() exists but pool-to-event-to-sitting pipeline not fully wired.

3b. Pool failure / cancellation handling

No clear workflow for when a pool fails to reach minimum candidates. No automatic refund/credit logic for failed pools. No student notification for pool status changes.

3c. Demand forecasting snapshots not surfaced

DemandForecastSnapshot model and takeDemandSnapshot() exist (~40% built). Snapshots are taken but never displayed in any staff UI. No recommendation engine for when to open new pools.

3d. Waitlist has no student-facing UI

pool_waitlist table exists, WaitlistStatus enum defined. No student page to view their waitlist position or status. No automatic promotion from waitlist when pool seats open.

3e. Pool merge validation gaps

Zod schema exists. Missing: validation that merged pools have compatible exam components and same pricing tier.

Student Portal

High

4a. No license progress dashboard

Students have no way to see their overall EASA license progress. No visualization of "modules passed / modules remaining" toward a license category (A1, B1.1, etc.). LicenseTarget model exists but has no student-facing progress view.

4b. No transcript / academic record

No printable/downloadable academic transcript. No consolidated view of all completed courses, exam results, attendance records.

4c. No certificate download

Students cannot download completion certificates or exam certificates. No certificate history page.

4d. Exam booking detail page — minimal info

app/student/exam-bookings/[id]/page.tsx — basic booking info only. Missing: bundle info, seat usage, venue/room details, preparation checklist.

4e. ResitBookingTab uses heuristic counting

app/student/exams/_components/ResitBookingTab.tsx:103-139 — counts pool memberships to estimate free resits instead of querying actual bundle data. Will show incorrect numbers.

4f. No payment gateway integration Planned

All payments are manual proof uploads. Stripe checkout exists in schema/webhook but flow not built. Tier 5 item #20 in future_plans.md.

4g. Student invoices hidden

Invoice system fully implemented but hidden behind feature flag. Documented in future_plans.md "Hidden Features" section with 3-file unhide process.

Staff / Admin Portal

Medium

5a. Dashboard lacks alerts and trends

No alert system for overdue payments, expiring bundles, low pool attendance. No trend indicators (up/down arrows) on dashboard metrics. No configurable dashboard widgets.

5b. No refund workflow

Wallet top-ups and payments exist but no refund/credit-back mechanism. No UI for staff to issue partial or full refunds. No refund reason tracking or approval chain.

5c. No payment reconciliation reporting

No way to match bank deposits against in-system payment proofs. No "unreconciled payments" view.

5d. No year/semester advancement workflow

Academic years and semesters exist but no bulk "advance all students to next semester" action. No end-of-year processing (calculate GPA, determine progression, flag failures).

5e. No student withdrawal workflow

Students can be set to SUSPENDED/ARCHIVED but no formal withdrawal process. No withdrawal reason tracking, no automatic financial settlement, no transcript on withdrawal.

5f. No bulk operations on users

No multi-select + batch action (activate, suspend, send credentials, assign to class). Each user must be managed individually.

5g. No role transition workflows

Changing a user's role is a dropdown change — no guided workflow. When promoting APPLICANT → STUDENT, no automatic enrollment setup.

5h. No cross-class timetable conflict detection

Individual class scheduling works. No cross-class view to detect instructor double-booking or room conflicts across multiple classes.

5i. No notification / messaging system

No in-app notifications for students or staff. No bulk messaging capability. Email sending exists (Resend) but no delivery tracking or template management UI.

5j. No GDPR / data tools

No data export for individual users (GDPR Article 15). No "right to erasure" workflow. Soft-delete exists but no user-initiated deletion request flow.

5k. Referrals have no staff UI

Referral model and ReferralStatus enum exist. No staff page to view, manage, or act on referrals.

5l. Settings — no permission configuration

Granular permissions exist in code (requirePermission()). No admin UI to view/edit permissions per role or per user. Must manage directly in the database.

EASA Part-147 Compliance

High — ~35%

EASA Part-147 — Approved Maintenance Training Organisation

Part-147 governs approved maintenance training organisations. The academy must maintain compliance with training records, instructor qualifications, attendance tracking, and examination standards. Several structural gaps exist that would be flagged in an EASA audit.

11a. No attendance enforcement per EASA requirements

EASA Part-147 mandates minimum attendance percentages for theoretical and practical training. Attendance is recorded but thresholds are not configured or enforced. No automatic alerts when students approach or breach minimum attendance.

11b. No qualified instructor verification

EASA requires instructors to hold appropriate qualifications for modules they teach. No mapping of instructor qualifications → authorized modules. No validation that assigned instructor is qualified for the class/module.

11c. No training record aggregation

EASA requires complete training records per student showing all theoretical instruction hours. No consolidated training hours view per student per module. No printable training record for regulatory submission.

11d. No practical assessment tracking

EASA Part-147 includes practical training components (workshop, lab). No practical assessment recording, no competency sign-off workflow. No distinction between theoretical and practical training hours.

11e. No regulatory reporting

No automated generation of EASA-required reports (student progress, examination statistics, instructor utilization). No export format compatible with national aviation authority (NAA) submission requirements.

12

EASA Part-145 — Maintenance Organisation

Critical — 0%

Complete Absence — Future Roadmap

Zero models, zero routes, zero UI. The academy plans to transition into EASA Part-145 (maintenance, repair, overhaul organisation). This is an entirely separate regulatory domain and a multi-month project.

12a. What Part-145 will require

  • Work order management — job cards, task assignments, sign-offs
  • Maintenance personnel licensing — engineer licenses (B1, B2, C categories), type ratings, recency
  • Tool/equipment calibration tracking — calibration certificates, due dates, quarantine for expired calibration
  • Component tracking — serialized parts, life-limited parts, modification status
  • Quality system — internal audit scheduling, finding tracking, corrective action management
  • Competence assessment — initial and continuation training for certifying staff
  • Approved data management — AMM, SRM, SB compliance tracking
  • Human factors training — tracking of mandatory human factors and safety training

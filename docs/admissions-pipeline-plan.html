Context

Aerojet Academy currently uses a simplified 4-step applicant flow: Register → Pay Registration Fee → Staff Approves → Portal Access. The academy previously relied on BambooHR for the full admissions pipeline (aptitude testing, interview scheduling, medical clearance). This plan brings everything in-house.


Who this affects: All programme types (FULL_TIME_4YEAR, FULL_TIME_2YEAR, MILITARY_1YEAR, MODULAR, EXAM_ONLY). Every applicant creates an Application record when the pipeline is enabled. EASA Part 147/145 compliance features (attendance, instructor management, practical training, OJT) apply to enrolled students.

Key Architectural Decisions

  • Separate Application model (not extending User) — User already has 83+ fields. Clean separation.
  • Application for ALL programme types — Every applicant gets an Application record when pipeline is enabled. Unified tracking.
  • Admin-configurable stage matrix — Per-programme stage toggle via JSON in SystemSettings. No code changes needed.
  • Configurable document requirements — Admin defines required docs (ID, certs, CV) per programme. No hardcoded fields.
  • Funding type independent of programme — Any programme can be scholarship, self-funded, or sponsored.
  • Scholarship bonding model — Scholarship = loan payback via bonding contract. Scores only (no cert downloads). Self-funded students are not bonded.
  • 5× minimum bank + stratified selection — Ensures fair question rotation and sub-topic coverage across exam sessions.
  • Part 147 compliance — Attendance, instructor recency, practical training records all auditable for NAA inspections.
  • OJT logbook as separate model — Multi-year tracking with supervisor countersignatures and ATA chapter coverage analysis.

Scholarship Bonding Model

The scholarship functions like a loan — students must "pay back" the investment through a contractual work obligation (bonding contract) at the academy's engineering facility after completion. During training, scholarship students do not receive individual course exam certificates — they only see their scores. This ensures the academy retains leverage until the bonding obligation is fulfilled.


Funding type is independent of programme. A 4-year full-time student can be either scholarship or self-funded. Bonding and certificate suppression are determined by fundingType (SCHOLARSHIP → bonded, no certs; SELF_FUNDED → not bonded, gets certs), not by programmeChoice.


Self-funded students (on any programme) are not bonded, are not served bonding contracts, receive certificates immediately upon passing, and are fully independent after graduation.


Contract lifecycle: ISSUED → SIGNED → IN_PROGRESS → FULFILLED / BREACHED. Certificates unlock when status = FULFILLED.

Post-Enrollment Divergence

  • Full-time 4yr: IntakeCycle → batch (~50) → Classes (~25) → AcademicYear + Semester. 2yr theory + 2yr OJT. Price includes both halves. If scholarship: bonded, scores only. If self-funded: not bonded, gets certificates.
  • Full-time 2yr: Theory only — same classes and exams as 4yr students (can share a class). No OJT included; OJT payable separately if desired.
  • Military (1yr): Same as full-time but with compressed AcademicTerms. Same bonding rules based on funding type.
  • Modular: No batch/class. Course catalog + admin-set completion deadline (default 24 months, override per student). Admin creates ad-hoc classes on demand.
  • Exam Only: Documents for pathway verification → exam booking access. No batch/class.

Payments: Full-time students pay via yearly milestones or full upfront. 4yr price covers theory + OJT.

Academy Operations Context

Batch → Class Structure

  • Currently 2 classrooms (25–28 seats each). Batch size = total capacity (~50).
  • Expanding for cabin crew, non-EASA, and more EASA courses.
  • Class 1: mornings (8–11 AM). Class 2: afternoons (12–3 PM).
  • Same instructor teaches both classes back-to-back.
  • 5–15 min break every hour.

License Categories & Exam Levels

  • B2 is higher than B1 — writing B2 exam automatically covers B1.
  • Same class may have students targeting B1.1 only and students targeting B1.1+B2.
  • They study together but write at different exam levels.

EASA Regulatory Changes (EU 2023/989 — June 2024)

Exam Structure:

  • Modules 9 & 10: Essay questions permanently removed — now purely MCQ
  • Module 10: MCQ count increased from 40 to 44 questions
  • Internal exam system must support per-module question counts (not a fixed global default)

New Syllabus Content:

  • M6: Composite materials & additive manufacturing (3D printing)
  • M7: EWIS & CDCCL
  • M9/M10: Safety Management Systems (SMS), occurrence reporting
  • M13: Modern avionics, fly-by-wire systems

Distance Learning (now permanent):

  • VCE (synchronous remote) and asynchronous learning formally allowed
  • VR/AR synthetic training devices permitted
  • Validates modular "class option" — online/remote classes possible

OJT: Competence-based assessment (replaces rigid checklist)

Experience: B1.1/B1.3/B2 = 12 months Part-145. A/B1.2/B1.4/B3 = 6 months.

Coming 2025+: Anti-exam-fraud (question randomization, proctoring), e-Licence rollout, language proficiency standards.


Exam Pool System (Already Built)

  • Pool = 1 classroom (max 28 seats), up to 4 modules per session.
  • Booking types: single, twin-pack, four-pack, group charter.
  • Multi-exam bookings go into separate sessions (can't write 2 at once).
  • Pool auto-fills. When full, new pool opens.
  • All programme types share the same pool system.

Anti-Cheat Measures

Client-Side (Deterrent)

  • Fullscreen API on test start
  • visibilitychange & blur listeners
  • CSS user-select: none + context menu blocked
  • Warning overlay on each violation
  • Auto-submit after threshold exceeded
  • Browser back/forward disabled

Server-Side (Authoritative)

  • expiresAt enforced — no late submissions
  • tabSwitchCount & fullscreenExits tracked
  • Auto-flag when thresholds exceeded
  • IP + user agent logged
  • One active session per user
  • Answer timestamps validated

Auto-Grading Logic

  • MCQ: Compare selected option to correctAnswer
  • True/False: Direct string comparison
  • Numeric Input: Parse as float, compare with tolerance (per-question or global epsilon)
  • Score: Σ(pointsAwarded) / Σ(points) → percentage
  • Passed: percentage ≥ aptitude_pass_threshold_pct

Anti-Cheat: Keyboard Auto-Submit

How It Works

  • document.addEventListener('keydown') on exam container
  • Any key press (except mouse clicks on answer options) triggers immediate auto-submit
  • Session marked autoSubmitted: true
  • Results rendered instantly — no second chance
  • Combined with fullscreen enforcement from aptitude system

Why This Works

  • Alt-Tab requires keyboard → caught
  • Ctrl-Tab requires keyboard → caught
  • Win key requires keyboard → caught
  • Students interact with MCQs via mouse clicks only
  • Essay questions: keyboard allowed only in designated textarea (exception handler)

Certificate Suppression (Scholarship Students)

After passing an internal exam, all students see their score. However, scholarship students (on any programme) cannot download individual module certificates — they only see scores. The scholarship acts as a loan; withholding certificates ensures the academy retains leverage until the bonding contract is fulfilled (status = FULFILLED). Enforced by checking Application.fundingType === 'SCHOLARSHIP' + BondingContract.status !== 'FULFILLED' in the certificate download API.


Self-funded students (on any programme) are not bonded and receive certificate downloads immediately upon passing.

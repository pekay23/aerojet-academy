# Design Gaps Analysis

## Overview

This document outlines identified design gaps in the Aerojet Academy portal system based on review of design logics, system architecture, and known issues.

## Design System Compliance Gaps

### 1. Portal UI/UX Design System (PORTAL-UI-SYSTEM.md)

- **Stat Card Pattern**: Not all dashboard pages consistently use the colored icon container + label + bold number pattern
- **Mobile Card Equivalents**: Some data tables lack mobile card equivalents at md: breakpoint
- **Status Badges**: Inconsistent use of `text-[10px] font-bold px-2 py-0.5 rounded-full uppercase border` pattern
- **Human-Readable Labels**: Some technical codes/jargon still appear in UI (e.g., raw enum values)
- **Glassmorphism Header**: Header uses `bg-background/80 backdrop-blur-md` but implementation may vary
- **Overflow Protection**: Some wrappers missing `overflow-x-hidden` or `min-w-0` + `shrink-0`

### 2. Typography Scale

- Inconsistent use of defined text sizes for section labels, timestamps, and secondary text across portals

### 3. Spacing Conventions

- Variable spacing in card headers, stat cards, and grid gaps not consistently applied
- Section gap in sidebar not uniformly `mt-8` between sections

### 4. Responsive Patterns

- Some tables lack mobile card equivalents
- Grid scaling not consistent across dashboard content
- Date display in header not consistently hidden below 1100px

### 5. Animations & Transitions

- Missing `animate-in fade-in slide-in-from-bottom-4 duration-500` on some page entries
- Inconsistent hover states and transition durations

### 6. Loading States

- Skeleton patterns not uniformly applied across all data-heavy pages
- Session hydration spinner missing in some authentication flows

### 7. Access Denied Pattern

- Not all unauthorized access points use the standardized `Access Denied` card pattern

## Known Issues (Design-Related)

### 1. Logo Aspect Ratio & CSS Warnings

- AATA Logo triggers hydration/layout warnings in multiple layout files
- Requires standardized Logo component across all layout entry points

### 2. Dashboard Analytics Latency

- Initial load of `/staff/reports` slow due to complex database queries
- Missing caching layer for analytic data

### 3. Email Verification Delays

- Potential rate limiting or queuing issues in email delivery system

### 4. UploadThing Feedback

- File picker lacks clear "Uploaded" state without user interaction

### 5. Prisma Enums vs DB Enums

- Occasional mismatches requiring manual synchronization

### 6. Missing Error Boundaries

- (auth) route segment missing `error.tsx`
- (auth)/(portal) missing `not-found.tsx`

### 7. Client/Server Import Boundary

- `@/lib/analytics/metrics` creates transitive server dependency for client components

### 8. Tailwind v4 Config Bridge

- Current setup uses compatibility bridge; full CSS-first migration pending

### 9. Prisma JSON Field Null Filtering

- Inconsistent use of `Prisma.DbNull` vs `null` for JSON field filtering

## Portal-Specific Gaps

### Staff Portal

- Sidebar navigation may not fully match design system specifications
- Dashboard analytics queries need optimization
- Financial reports section lacks consistent card patterns

### Student Portal

- Wallet transactions table may lack mobile equivalent
- Course enrollment flow has inconsistent button patterns
- Exam pooling interface needs mobile optimization

### Applicant Portal

- Course detail pages lack consistent section break images
- Admissions pipeline steps visualization needs enhancement

### Instructor Portal

- Practical assessment interface lacks standardized card patterns
- OJT logbook viewing needs mobile optimization

### Examiner Portal

- Exam preview and compliance reporting sections need design consistency
- Question bank management interface lacks mobile equivalents

### Public Portal

- Hero sections may not fully implement visual plan imagery
- Credibility section logo display has aspect ratio issues

## EASA 147/145 Compliance Gaps

### Transition Features

- Missing visual indicators for EASA vs internal exams in student dashboard
- Incomplete Part-145 OJT facility tracking in student profiles
- Attendance tracking for Part-147 compliance needs enhanced reporting

### Organizational Transition

- No clear UI distinction between Part-147 training and Part-145 experience tracking
- Missing automated reminders for Part-145 experience expiration

## System-Wide Gaps

### 1. Theme Consistency

- Aerojet blue branding not consistently applied across all portals
- Dark mode implementation may have inconsistencies

### 2. Form Validation

- Multi-step forms may lose data on back navigation in some cases
- Error message presentation not standardized

### 3. Data Tables

- Some tables lack proper loading states
- Pagination controls inconsistent across portals

### 4. Modals & Overlays

- Not all modals use standardized shadcn/ui Dialog component
- Transition animations for overlays not consistent

### 5. Navigation

- Breadcrumb generation may not handle nested routes correctly
- Mobile sidebar trigger button styling varies

### 6. Footer

- Subtle footer pattern not consistently implemented across all pages

## Recommendations

1. **Implement Design System Audit**: Create automated checks for PORTAL-UI-SYSTEM.md compliance
2. **Address Known Issues**: Prioritize fixes for logo warnings, dashboard latency, and missing error boundaries
3. **Standardize Portal Components**: Create shared components for stat cards, tables, and modals
4. **Enhance EASA Compliance Tracking**: Add visual indicators and reporting for Part-147/145 requirements
5. **Improve Mobile Responsiveness**: Ensure all tables have card equivalents and touch targets are adequate
6. **Add Caching Layer**: Implement Redis or similar for dashboard analytics
7. **Standardize Error Boundaries**: Add missing error.tsx and not-found.tsx files
8. **Create Design Token Library**: Centralize spacing, typography, and color values

## Conclusion

The design gaps identified span UI consistency, known technical issues, portal-specific implementations, and EASA compliance features. Addressing these gaps will improve user experience, reduce technical debt, and ensure regulatory compliance.

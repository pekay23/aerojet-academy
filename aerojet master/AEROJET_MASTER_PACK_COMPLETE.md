## 6. EXAM POOLING SYSTEM

### 6.1 Pooling Concept

**What is an Exam Pool?**
- A single exam sitting that brings together 25-28 candidates
- Each candidate takes ONE module per pool
- Supports up to 4 different module codes within the same sitting
- Example: Pool A might have:
  - 7 candidates taking M1
  - 8 taking M7
  - 6 taking M8
  - 5 taking M15
  - **All in the same exam session**

### 6.2 Pool Economics

**Why Pooling Works:**
- **Partner examiner** travels from Europe to Ghana
- Fixed cost: ~€15,000-20,000 per trip (travel, accommodation, fees)
- Need minimum revenue to cover costs: **€25,000**
- Pool model: €300 × 25 = €7,500 per pool
- Target: 3-4 pools per event = €22,500-30,000 total

**Student Benefits:**
- €300 per exam (vs €520 individual)
- Predictable scheduling (quarterly events)
- Community learning (group prep clinics)

### 6.3 Event & Pool Structure

**Exam Event (Quarterly):**
- Duration: 2-3 days
- Contains: 3-6 pools
- Scheduled: Every ~3 months
- Minimum revenue: €25,000 to proceed

**Go/No-Go Decision (T-21):**

Event proceeds if **ANY** of these thresholds met:
1. **3 pools** with 25+ candidates each (€30,000 revenue), OR
2. **2 pools** (25+ each) + 15 individual seats (€27,800+ revenue), OR
3. **60 total confirmed** paid seats (€25,200+ revenue)

If minimum not met: Event postpones, all bookings roll to next event automatically

**Pool Statuses:**
- `DRAFT` - Being created by admin
- `OPEN` - Accepting bookings (<23 members)
- `NEAR_FULL` - 23-24 members (almost ready)
- `CONFIRMED` - 25+ members (locked, payments captured)
- `LOCKED` - Exam completed, no changes
- `COMPLETED` - Results published
- `FAILED` - Did not reach 25 members (funds released)

### 6.4 Pool Rules

**Capacity:**
- Minimum: 25 candidates
- Maximum: 28 candidates
- Optimal: 25-26 (leaves room for last-minute additions)

**Module Diversity:**
- Maximum: 4 different module codes per pool
- Once 4 modules exist, new joiners must choose from existing 4
- Prevents fragmentation

**One Module Per Pool:**
- Each candidate takes EXACTLY ONE module per pool
- Want to take multiple modules? Join multiple pools
- Example: Student taking M1, M7, M8 must join 3 different pools

**Confirmation Rules:**
- Auto-confirms at 25 paid members
- All held funds are CAPTURED (deducted) upon confirmation
- No refunds after confirmation (examiner committed)

**Failure Rules:**
- Pool fails if < 25 members by T-21
- All held funds RELEASED (returned to availableBalance)
- Members can:
  - Join another pool in same event
  - Auto-roll to next event at no cost
  - Upgrade to individual seat (+€220 top-up)

### 6.5 Pooling Technical Implementation

**Race Condition Prevention:**
```typescript
// Use Serializable transaction isolation
await prisma.$transaction(async (tx) => {
  // 1. LOCK pool row (SELECT FOR UPDATE)
  const pool = await tx.$queryRaw`
    SELECT * FROM "ExamPool" WHERE id = ${poolId} FOR UPDATE
  `
  
  // 2. Check capacity AFTER lock
  if (pool.currentMemberCount >= pool.maxCandidates) {
    throw new Error('Pool is full')
  }
  
  // 3. Process join...
  // 4. ATOMICALLY increment count
  await tx.examPool.update({
    where: { id: poolId },
    data: { currentMemberCount: { increment: 1 } }
  })
  
  // 5. Check for auto-confirmation (25+ members)
  if (updatedPool.currentMemberCount >= 25 && pool.status === 'OPEN') {
    await confirmPool(tx, poolId)
  }
}, {
  isolationLevel: Prisma.TransactionIsolationLevel.Serializable
})
```

### 6.6 Payment Processing

**Pool Join (Reserve Funds):**
1. Check availableBalance ≥ €300
2. Hold funds: `reservedBalance += 300`
3. Update: `availableBalance = balance - reservedBalance`
4. Create `RESERVE` transaction
5. Create membership with `status: RESERVED`

**Pool Confirmation (Capture Funds):**
1. Pool reaches 25 members
2. For each member:
   - Deduct from balance: `balance -= 300`
   - Release from reserved: `reservedBalance -= 300`
   - Update membership: `status: CONFIRMED`
   - Create `PAYMENT` transaction
   - Send confirmation email

**Pool Failure (Release Funds):**
1. Pool fails to reach 25 by T-21
2. For each member:
   - Release from reserved: `reservedBalance -= 300`
   - No change to balance
   - Update membership: `status: CANCELLED`
   - Create `RELEASE` transaction
   - Send failure notification with options

### 9.3 Exam Pool Rules

**Booking Rules:**
1. Pool seat = ONE module only
2. Want multiple modules = join multiple pools
3. First-come, first-served (after payment clears)
4. Maximum 28 candidates per pool
5. Maximum 4 different modules per pool
6. Cannot join same pool twice
7. Cannot change module after pool confirmation

**Confirmation Rules:**
1. Pool auto-confirms at 25 paid members
2. All funds captured upon confirmation
3. No refunds after confirmation
4. Pool status changes: OPEN → CONFIRMED

**Failure Rules:**
1. Pool fails if < 25 members by T-21
2. All held funds released
3. Members get options:
   - Join another pool (if available)
   - Roll to next event (no cost)
   - Upgrade to individual (+€220)

**Event Rules:**
1. Event proceeds if minimum revenue met (€25,000)
2. Go/No-Go decision at T-21 (21 days before)
3. If event fails, all bookings roll forward
4. No cash refunds, wallet credits only

### 9.4 Wallet Rules

**Balance Types:**
- `balance` - Total funds in wallet
- `reservedBalance` - Held for pools
- `availableBalance` - Can be used (computed: balance - reserved)

**Operations:**
1. **Top-up:** Staff approval required
2. **Reserve:** Automatic on pool join
3. **Capture:** Automatic on pool confirmation
4. **Release:** Automatic on pool failure
5. **Payment:** Manual for course purchases

**Restrictions:**
1. Cannot withdraw funds (wallet credit only)
2. Cannot transfer between wallets
3. Cannot use reserved funds
4. All transactions logged and auditable
